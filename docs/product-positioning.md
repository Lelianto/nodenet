# NodeNet product positioning

## Category

**Governance-aware repository intelligence for AI agents.**

NodeNet helps an agent change the right code, understand the blast radius, and
involve the right people. Its graph is the mechanism; safe, reviewable change
is the product outcome.

## Product promise

> Connect code structure, living context, ownership, authority, and the actual
> Git change so an AI agent can route work, respect constraints, and request
> the right review before changing code.

The product has three verbs:

1. **Route** — identify the smallest relevant file and symbol set.
2. **Govern** — surface applicable constraints, owners, authority, and required
   approval without dropping mandatory context to meet a token budget.
3. **Verify** — evaluate the real diff for blast radius, boundaries, severity,
   and reviewers.

Token efficiency is a product constraint, not the primary promise. NodeNet
keeps governed context bounded so safety does not require loading the whole
repository into an agent prompt.

## Claims supported today

- Deterministic, local-first repository and governance analysis.
- Lean routing and progressive `route`, `map`, `evidence`, and `source`
  disclosure.
- Complete mandatory-context recall in the current ten-scenario deterministic
  evaluation.
- Impact, ownership, authority, and reviewer evidence unavailable to plain text
  exploration in the live experiments.
- Compact payloads and explicit accounting, budget overflow, and provenance.

## Claims requiring more evidence

NodeNet must not promise that it always reduces total task tokens, replaces
source reading, or has a universal graph-node break-even threshold. Those
claims require repeated, model-in-the-loop task A/B evidence with provider
telemetry.

The publishable efficiency claim is deliberately narrower:

> NodeNet reduces repository-exploration waste while adding deterministic
> governance and change-impact evidence.

## Competitive frame

Repository-memory tools primarily optimize repeated understanding. Search and
RAG tools primarily optimize discovery. Static ownership and policy tools cover
one governance surface each. NodeNet joins retrieval, living constraints,
ownership, authority, Git impact, and reviewer resolution in one auditable
change workflow.
